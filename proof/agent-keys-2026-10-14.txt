Agent keys (PLAN 5.31, docs/59 §3.16: the SIWE + ReCaps idea, done with the passkey) — 2026-10-14

What: the company's other agents (Claude Code, OpenClaw, a cron job) reach the
account through `tameion-mcp`. Until today anyone who knew the policy address
could read the inbox or start a pass. Now the owner's passkey mints a
capability token for an agent — scopes among read / run / prepare / import, a
label, an expiry of at most a year — and the first key locks the account: from
then on the read / run / prepare / import routes require
`Authorization: Bearer <token>` carrying the scope. The service keeps only
sha256(token). Revoking the last key reopens the account. Routes the passkey
signs anyway (execute), the chain bounds (pay-due, apply), or that are the
token flow itself stay open. `tameion-mcp` sends `TAMEION_TOKEN`. The page
keeps the key it minted so the owner's own browser keeps working; a fresh
browser is asked to paste a key.

Code: `level1::{AgentToken, TOKEN_SCOPES, scope_for, token_hash, token_challenge,
token_revoke_challenge, token_allows}`; routes `prepare-token`, `token-signed`
(passkey assertion verified against the owner's on-chain key, fresh, unused),
`prepare-token-revoke`, `token-revoke-signed`; `App::token_gate` in front of the
dispatcher; inbox `agentTokens` (ids, labels, scopes, expiries — never secrets)
and `gated`. Unit tests: an open tenant stays open; once a token exists the
bearer is required; unknown, wrong-scope and expired keys are refused;
whitespace around a key is ignored; the scope table (inbox/records → read,
run → run, prepare-* and fund → prepare, bills → import; token routes, execute,
pay-due, watch → open). Card "Your other agents" on `/`: scopes, label, days,
"Mint with my key"; the minted key shown once; the list with one-tap Revoke.
