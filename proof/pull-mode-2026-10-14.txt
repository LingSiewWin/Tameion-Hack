Pull mode (PLAN 5.26, docs/59 §3.2: the ERC-5827 idea) — Arc testnet, 2026-10-14

What: the company's USDC never moves into Tameion. `BudgetPolicyPull` holds
nothing; the bill wallet grants it an ERC-20 allowance and every payment is a
`transferFrom` inside the same caps, payee list, modes, delays and `Paid`
event as the holding policy. What the agent can reach is the smaller of the
wallet's balance and the allowance, so the allowance is a second cap the
treasurer holds in their own wallet and can cut to zero with one
`approve(policy, 0)` from any wallet software, without Tameion.

Contract: contracts/src/BudgetPolicyPull.sol (constructor takes usdc + source,
then the base policy's arguments; `balanceUsdc()` = min(balance, allowance);
`allowanceRemaining()`; `_send` = safeTransferFrom(source, to, amount); native
coin refused; six decimals required). Tests: contracts/test/BudgetPolicyPull.t.sol,
14 tests — the policy holds nothing and the wallet pays; reach is min(balance,
allowance); approve(0) cuts the agent off (InsufficientBalance(25, 0)); the
reserve floor means "leave that much in the wallet"; 18-decimal token and
zero source refused; native refused; unattested payee, per-action cap,
replay, over-reach, principal-only withdraw (pulls from the wallet),
settleAsPrincipal, and the Paid event. forge: 103 tests (89 + 14).

Service / page: `POST /api/level1/deploy {pull:true}` deploys BudgetPolicyPull
with `watched` as the source (bytecode snapshot contracts/bytecode/BudgetPolicyPull.hex);
the tenant records `kind: pull`; the inbox carries `pull {wallet, usdc,
allowance, walletBalance, suggestedAllowance (30 days at the daily cap),
approveData, revokeData}`; on `/` the Start form has "Keep the money in my
wallet …" (checked by default when a browser wallet is present), the "Fund
it" card is replaced by "Allow it" with "Allow from this browser" and "Cut it
to zero" (eth_sendTransaction on USDC from the bill wallet) and the exact
approve call in words for any other wallet. Agent key files are reused per
owner, never overwritten (one passkey, several policies).

Found on the way and fixed in this build: the first pass of a 90-day tenant walked
15M blocks chunk by chunk and tripped the public node's -32005 rate limit for every
other call (the relayer's passkey transactions failed) — the scanner now reads
newest-first within a time budget (TAMEION_PASS_SCAN_SECS, default 600), pauses
400 ms between slices, bisects the node's history horizon on -32014, and the
report says how many days it read; a pass the previous process was running is
marked failed on restart instead of showing "checking" for ever; status read the
policy address's own USDC (always 0 in pull mode) instead of balanceUsdc().
