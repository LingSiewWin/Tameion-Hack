# Passkey principal, 2026-10-02: a browser passkey is the only key that can name a payee

What this shows: a policy whose principal is `PasskeyPrincipal` (contracts/src/
PasskeyPrincipal.sol). Its only key is a P-256 passkey created by Chrome through
the real WebAuthn API (web/passkey/index.html), signed into a CDP virtual
authenticator (ctap2, internal transport, user verification on). The relayer
pays gas and holds no authority. Driven by scripts/prove_passkey.sh.

Not shown here, and not claimed:
- A physical device. The authenticator is Chrome's virtual one: the page,
  the browser's WebAuthn encoding, the DER signature and Chrome's
  clientDataJSON are real; Touch ID / Face ID is not. That run needs the
  founder's hand.
- Arbitrum Sepolia deployment. Treasury and agent hold 0 ETH there
  (checked 2026-10-02). Section 4 does verify this exact signature with
  Arbitrum Sepolia's P-256 precompile, read-only.
